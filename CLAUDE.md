# Markup MVP (Kommently)

Visual feedback SaaS: a team loads a **live website** (via our proxy, inside an iframe) or **uploaded documents** (PDF/images), drops **pins** on it, and discusses each pin in a **comment thread**. Guests review via a public share link. Multi-tenant (organizations), paid plans with trial.

Also verify server edits with `node --check <file>`. Production deps: don't upgrade existing packages without asking.

## Server (`server/`)

- `app.js` middleware order matters. Payment webhooks (`/api/billing/webhook/{razorpay,paypal}`) and `/api/proxy` use `express.raw` and are mounted **before** the JSON parser. After that: mongoSanitize, hpp, globalLimiter, CSRF (double-submit `markup_csrf` cookie + `X-CSRF-Token`; skipped for Bearer, the pre-login `/api/auth/*` endpoints in `PUBLIC_AUTH_PATHS`, `/api/guest/*`, `/api/email/*` and `/api/support/contact`), then the routes. JSON body limit is 1mb. Public endpoints: `/api/health` (503 if Mongo is down, reports Redis), `/api/plans` (also returns `signupMode`, `trialDays`), `/api/email/unsubscribe`, `POST /api/support/contact` (website contact form: `supportLimiter` 5/h, honeypot `website` field, sent to `SUPPORT_EMAIL` or `SMTP_FROM` with the sender as Reply-To).
- **Multi-core** (`utils/cluster.js`): with `REDIS_URL` set, `server.js` runs a primary that forks `WEB_CONCURRENCY` workers (default: cores, max 4) sharing the port and replaces crashed ones; workers get `CLUSTER_WORKERS` and socket.io then accepts WebSocket only (long-polling can't span processes). Without Redis it stays single-process. Per-process state (proxy caches, `relayFirstDomains`) is fine to be per worker.
- Proxy upstream requests use shared keep-alive agents (`directHttp(s)Agent`, `relayHttp(s)Agent`); a GET that hits a just-closed kept-alive connection (`ECONNRESET`) is retried once.
- **Logging** (`utils/logger.js`, pino + pino-http, mounted first in `app.js`): one line per request (method, URL, status, ms, `userId`, IP, `X-Request-Id`, and the `{message}` of 4xx/5xx responses); colored one-line output via `pino-pretty` (proxy requests shown as `proxy <target url>`; `LOG_FORMAT=json` for JSON); `OPTIONS` preflights are not logged. Query tokens (`token`, `rt`, …), auth headers and cookies are redacted; bodies are never logged. `LOG_LEVEL` sets the level; `/api/health` is not logged. In handlers use `req.log`; the error handler sets `res.err` so 5xx lines carry the stack.
- **SMTP**: transport timeouts are 10s connect/greeting (OTP and password-reset requests wait for the send). Diagnose with `npm run check:smtp [to@email]` (in Docker: `docker compose exec server node scripts/checkSmtp.js`): TCP reachability, login, optional test email, with hints per error code.
- `server.js` loads `instrument.js` (Sentry, no-op without `SENTRY_DSN`; scrubs tokens/passwords/cookies, incl. share/invite/reset tokens in paths) before anything else. Sentry covers errors, tracing (`SENTRY_TRACES_SAMPLE_RATE`), profiling of traced requests (`@sentry/profiling-node`, `SENTRY_PROFILE_SAMPLE_RATE`), logs (pino integration, from `SENTRY_LOG_LEVEL`, default warn) and metrics (`metric(name, attrs)` from `instrument.js`: `user.signup`, `project.created`, `pin.created`, `comment.created`). It starts the email worker and billing scheduler, and shuts down gracefully on SIGTERM.
- **Redis** (`utils/redis.js`, optional `REDIS_URL`): BullMQ email queue (`utils/emailQueue.js`, retries with backoff), BullMQ daily billing job (`utils/scheduler.js`, runs once across instances), shared rate limits (`middleware/rateLimiters.js`, incl. per-email limits on login/reset/OTP), socket.io Redis adapter. Without Redis everything falls back to memory (single instance). Request-path commands use a fail-fast connection so a Redis outage degrades instead of hanging requests.
- `server.js` sets up socket.io. The JWT comes from `handshake.auth.token` (session token checked; proxy tokens refused). Rooms are `user:<id>` and `project:<id>` (`join:project` checks project access via `resolveAccess`; presence uses `fetchSockets()` so it works across instances). Controllers emit through `req.app.get('io')` with these events: `pin:*`, `comment:*`, `notification:new`, `presence:*`.
- **Auth** (`middleware/auth.js`): reads the JWT from `?token=`, then the Bearer header, then the `markup_token` cookie. A user has one active session at a time (`sessionToken`); a mismatch returns 401 `SESSION_REPLACED`. Auth sets `req.user` and `req.organization` (with plan limits merged in) and runs the trial-expiry check.
- **Roles and access (standard model)**: an **organization role** per user (`User.role`: `superadmin` > `owner` > `admin` > `member` > `guest`, `middleware/roles.js` → `authorize()`, changed on the Team page via `PATCH /api/workspaces/people/:userId/role`) decides org-wide actions (billing, team, integrations, creating/renaming/deleting workspaces). An **access level** (`utils/access.js`: `view` < `comment` < `manage`) decides what someone can do on a workspace or project, and flows down from a workspace to its projects. Effective project level = `manage` for org owners/admins and the project's creator, else the highest of the project grant (`Project.members` + `Project.memberAccess[{user, level}]`; members without an entry: member→comment, guest→view) and the workspace grant (`Workspace.members[{user, level}]`); guests are capped at `comment`. `projectAccess`/`pinAccess` set `req.access`; routes gate with `requireAccess('comment'|'manage')` (pins/comments/versions-create: comment; project edit/delete/share/members/invitations, version edit/delete: manage); `workspaceAccess(level)` does the same for `:workspaceId` routes (members, invitations, share). People who manage a workspace can create projects in it (`canCreateProject`) and see Settings → Workspaces for it. Responses carry `access` (`GET /projects`, `GET /projects/:id`) and `myLevel` (`GET /workspaces`); the client gates the UI on these (comment mode/composer, card menus, New project). Each user belongs to one org (`User.organization`). Lookups by child id are scoped to the authorized project (`Pin.findOne({ _id, project })`).
- **Org limits / lock** (`middleware/orgLimits.js`): returns 403 with one of `ORG_LOCKED`, `PROJECT_LIMIT`, `MEMBER_LIMIT`, `GUEST_LIMIT`, `STORAGE_LIMIT`, `FEATURE_NOT_AVAILABLE`. Seats count users plus pending invitations (owner included). Effective limits = plan limits + PlanConfig + per-org `limitOverrides` (`getEffectiveLimitsAsync` in `config/plans.js`). Storage quota (`utils/storage.js`): `Organization.storageUsedBytes` counter, reserved after multer on every upload route, released by the delete cascades.
- **Deletes** go through `utils/cascade.js` (project/pin/comment: child records + files + storage). Uploads keep a mimetype-derived extension; `/uploads` is served with `nosniff`, and non-image/PDF files are sandboxed and downloaded.
- **Guest share links**: every guest endpoint goes through `loadSharedProject` (enabled, expiry, password via the `X-Guest-Access` token issued by `getGuestProject`; writes also need an unlocked org). Share links need a paid plan or trial. Guests can pin too (with comments allowed): the client posts the pin, then its first comment; `getGuestPins` returns `firstComment` for the list preview.
- **Comment HTML** is sanitized on write (`utils/sanitizeComment.js`, Quill allowlist) and again with DOMPurify in `client/src/utils/renderCommentBody.js`.
- **Conventions**: controllers are `exports.fn = asyncHandler(async (req,res)=>…)`. Errors are `res.status(x).json({ message, code? })`. Successes return named objects like `{ project }` or `{ token, user }`, with 201 on create. Routes do `router.use(auth)`, then `projectAccess`, `authorize`, and the limit checks. Activity is logged fire-and-forget with `utils/activityLogger.js`.

### Models (`server/models/`)
- **Organization**: plan (`trial|free|starter|pro|enterprise`), `limits{maxMembers,maxGuests,maxProjects,maxStorageMB,hasIntegrations,hasActivityLogs,hasVersionHistory}`, `limitOverrides` (superadmin), trialEndsAt + `trialReminders`, isLocked/lockedReason, `subscription{status,currentPeriodEnd,provider,cancelAtPeriodEnd,…}`, `billingDetails` (buyer info for invoices), `storageUsedBytes`, `deletionScheduledAt`.
- **Project**: `projectType` is `website` (websiteUrl) or `document` (`documents[]` up to 10, pageCount via pdf-parse). Other fields: members, status (active/archived), projectStatus (workflow), `shareSettings{enabled,token,passwordHash,allowComments,expiresAt}`.
- **Pin**: pageUrl, xPercent/yPercent (doc %), `selector` + elementOffsetX/Y, viewportX/YPercent, documentWidth/Height, deviceMode (desktop 1440/tablet 768/mobile 375), pinNumber (unique per project), screenshot, status pending/resolved, version, createdBy or createdByGuest.
- **Comment**: pin, author/authorGuest, body (HTML from Quill), attachments, parentComment, mentions.
- **Workspace**: groups projects inside an organization (e.g. one per client). `Project.workspace` (null = the org's default workspace, created on first use by `utils/workspaces.ensureDefaultWorkspace`). Plan and billing stay on the organization. API `GET|POST /api/workspaces`, `PATCH|DELETE /api/workspaces/:id` (owner/admin; the default one can't be deleted, deleting moves its projects to the default), `GET /api/workspaces/people` (org users to pick from). `POST /projects` takes `workspace`, `GET /projects?workspace=` filters, `PATCH /projects/:id {workspace}` moves. Limit `maxWorkspaces` (free 1, starter 3, pro/enterprise unlimited; 403 `WORKSPACE_LIMIT`; per-org override in admin).
  - **Members** (`Workspace.members[{user, level}]`, `PUT /api/workspaces/:id/members {members:[{userId, level}]}`): org users with that level on every project of the workspace, incl. future ones (`resolveAccessAsync` in projectAccess/pinAccess/socket `join:project`; `getProjects` uses `visibleProjectsQuery`). They are not added to `Project.members`, but `utils/workspaces.workspaceMemberUsers` adds them to notification recipients (`notifier.getRecipients`, `notificationHelper`) and `GET /projects/:id` returns them as `workspaceMembers` (client merges them into the mention/presence list). Guest-role users stay view-only (pins/comments need member+).
  - **Invitations** (`POST|GET /api/workspaces/:id/invitations {emails, role: member|guest, level}`; project invites also take `level`, default comment; `Invitation.level`): org users are added at once, users of other orgs are refused, new emails get an `Invitation` with `workspace` (not `project`) and the usual `/signup?token=` email; signup accepts it (joins org + workspace, returns `invitedWorkspaceId`, client opens that workspace). Team page invite can target whole workspaces; Settings → Workspaces → Members has invite-by-email and pending invites (resend/cancel via `/api/invitations/:id`).
  - **Review link** (`Workspace.shareSettings`, `POST|PATCH|DELETE /api/workspaces/:id/share`, needs a paid plan or trial): `/review/w/:token` (`GuestWorkspacePage`, `GET /api/guest/workspace/:token`) lists the workspace's active projects; each opens on the normal guest page with the token `<workspaceToken>.<projectId>`. `utils/sharing.findShared` resolves both token kinds for every guest endpoint (governing settings on `req.share`); the guest access token is bound to the workspace, so one password covers all its projects (kept per link in `sessionStorage`). The guest proxy accepts projects shared either way (`isProjectShared`, 60s cache).
- Also: Version (snapshot; creating one tags un-versioned pins), Invitation (5-day token), Notification, Activity, Integration (slack/jira/discord/teams, org-wide or per project; Jira token masked in responses), Invoice (status `pending|paid|failed|void|refunded`; unique per org+billingMonth; `invoiceNumber`, `seller`/`buyer`/`tax` snapshots), Counter (atomic sequences), PlanConfig (admin price/limit overrides incl. `priceInr`, 5-min cache), PaymentSettings (singleton: activeProvider, allowDowngrades), EmailVerification (OTP, TTL). `User.emailNotificationsEnabled` is the global notification-email opt-out.

### Website proxy (the core trick)
- The iframe src is `/api/proxy?url=…&projectId=…&token=…[&guest=true]`. `token` is a 24h **project-scoped proxy token** (`utils/proxyToken.js`, returned by `GET /projects/:id` and the project list), never the session JWT; the normal auth middleware rejects it. The handlers are `controllers/proxy.controller.js`, `middleware/proxyAuth.js` and `utils/proxyRewriter.js`. Unauthenticated (guest) requests must hit a project with an enabled, unexpired share link.
- SSRF guard (`utils/ssrfGuard.js`): only public http(s) targets; private/loopback/link-local IPs are blocked at DNS lookup and on every redirect (`PROXY_ALLOW_PRIVATE=true` for local dev only). Responses are capped (`PROXY_MAX_BYTES`), caches are bounded.
- The server fetches **directly first** (assets of directly-fetched pages are proxied through Express too). When an origin blocks or throttles the server (bot wall on a page, 403/429/503 on an asset, timeout/reset), it retries through the Cloudflare relay (`FALLBACK_RELAY_URL`, signed `rt` token from `utils/relayToken.js`) and remembers the domain for 1h (`relayFirstDomains`), so that page's assets go via the relay. Last resort: optional `OUTBOUND_PROXY`, then the blocked/error page. Sub-resource auth reads the project proxy token from the `__markup_proxy_ctx` cookie (pages loaded without `?token=` keep the cookie's token for the same project). Page and form redirects are not followed server-side: the 3xx goes back to the browser rewritten into `/api/proxy?url=…` so the site's `Set-Cookie` (e.g. a login session) is stored; site cookies are re-scoped to `Path=/; SameSite=Lax`. It strips XFO/CSP and rewrites cookies (never lets the site set `markup_*` cookies).
- It sets the `__markup_proxy_ctx` cookie. A catch-all in `app.js` 307-redirects stray non-API requests that carry this cookie back into the proxy.
- `proxyRewriter.js` rewrites the HTML with cheerio (links, srcset, CSS `url()`, strips `integrity`). It then **injects a script** that:
  - patches fetch/XHR/history;
  - draws the pin overlay;
  - takes viewport screenshots (`captureViewport`): html2canvas 1.4.1 first, html2canvas-pro (`/api/vendor/pro`, parses oklch/oklab) when it fails, a fast retry on timeout. Before cloning it pre-renders `object-fit` images at their on-screen crop, flattens `background-clip:text`, holds back unloaded/lazy image sources (they shifted the layout) and blanks offscreen images; turns off `scroll-behavior:smooth` on the page while cloning (else the copy captures the top of the page), leaves `display:none` elements out, pins the live margins of first/last children of elements with `::before/::after` (html2canvas inserts those as real nodes and breaks `:first-child` margin rules); the clone gets animations jumped to their end state, `overflow-anchor:none` and is re-scrolled to the page position after these changes; scale 1 (CSS pixels, ~50–120 KB JPEG); pin overlay excluded. Each `MARKUP_CLICK`/`MARKUP_SCREENSHOT` pair shares a `clickId`; `ProjectView` routes a screenshot only to the popup or saved pin of that click (Post never waits; late ones are uploaded via `PATCH …/screenshot`).
- Pin rendering uses `querySelector(selector)` plus the element offset, and falls back to the document percentages. It re-renders on scroll/animation and at 0.5/1.5/3/6s after load.
- **postMessage protocol** (all `MARKUP_*`). Client side is `client/src/hooks/useIframeMessages.js`.
  - iframe → parent: `READY`, `NAVIGATING`, `SCROLL`, `CLICK`, `SCREENSHOT`, `PIN_CLICK`, `BLOCKED` (`{kind: blocked|unreachable, domain}`, posted by the proxy's error page; `ProjectView` turns Comment off and shows a recovery panel)
  - parent → iframe: `NAVIGATE`, `PIN_MODE`, `UPDATE_PINS`, `SELECT_PIN`

### Notifications
`utils/notifier.js` is the hub.
- **Email**: members get emails, respecting `User.emailNotificationsEnabled` and `User.mutedProjectEmails`. `utils/emailQueue.js` batches per recipient for `EMAIL_BATCH_DELAY_MS` (default 5 min) and sends a digest when there are several (Redis/BullMQ when configured, else in memory). Notification emails get an unsubscribe link and `List-Unsubscribe` headers (`utils/unsubscribe.js`, `routes/email.routes.js`); footers show `COMPANY_POSTAL_ADDRESS`. Templates live in `utils/email/templates.js`: pure functions returning `{subject, html, text}`. They're built from the shared blocks in `utils/email/layout.js` (app green theme, table-based, auto-escaped; `**bold**` markup in text). `utils/mailer.js` only sends them. Preview them all with `npm run preview:emails [outDir]`. Set the optional `EMAIL_LOGO_URL` env var to use an image logo instead of the text "K" mark.
- **In-app**: `utils/notificationHelper.js` creates the Notification and emits it.
- **Integrations**: `{slack,discord,teams}Notifier.js` send webhooks. `jiraSync.js` creates an issue on `pin.created`.
- **Mentions**: written as `@[Name](id)` or Quill `data-id` (`utils/mentionHelper.js`).

### Billing
- **Plans** (`config/plans.js`):
  - free: 2 projects
  - starter: $12, 15 projects
  - pro: $29
  - enterprise
  - trial: 30 days, **Pro limits**, no card. New signups land on it; onboarding offers it by default.

  Admin overrides come from PlanConfig.
- **Providers** (`payments/`): Razorpay (INR, `priceInr` or `price × RAZORPAY_USD_INR_RATE`) and PayPal (USD). Both use the same interface, incl. `refundPayment`. `settleInvoice.js` is the single path that marks an invoice paid: atomic claim, assigns the tax invoice number/GST (`invoiceIssuer.js`), activates the plan, sends the receipt. Renewal invoices (`billingMonth` set) don't extend the period again. `refundInvoice.js` records refunds; a full refund of the current period moves the org to free.
- `POST /billing/upgrade` never takes payment: only free, or a downgrade from an active paid plan (else 402). `POST /billing/cancel|resume` (cancel at period end), `GET|PUT /billing/details` (buyer details). Admin: set plan, extend trial, limit overrides, refund (`routes/admin.routes.js`).
- **Daily job** (`scripts/runBilling.js`, scheduled by `BILLING_CRON_ENABLED=true` or `npm run billing`): renewal invoices 24h before `currentPeriodEnd` (skips cancelled), reminders on days 4/7/9, lock after `dueAt` (voids invoices of orgs that left paid plans), ends cancelled subscriptions, trial emails (7/3/1 days) and trial lock, purges orgs past `deletionScheduledAt` (invoices kept), retention (notifications 180d, activity 365d, invitations 30d past expiry). Dates use `utils/billingDates.js` (`addMonthsUTC`). `clearBillingLock` only lifts billing/trial locks, never manual admin locks.
- **GDPR**: `GET /auth/organization/export` (JSON), `POST /auth/organization/delete` (password + name, 7-day grace, locks the org), `POST /auth/organization/cancel-deletion`.

## Client (`client/src/`)
- **Routes** (`App.js`, lazy pages):
  - Public: `/login`, `/signup`, `/onboarding`, `/forgot-password`, `/reset-password/:token`, `/review/:shareToken` (guest).
  - Private: `/dashboard`, `/settings?tab=`, `/integrations`, `/profile`, `/project/:projectId/members`, `/project/:projectId` (no sidebar).
- **API**: `services/api.js` (axios, `REACT_APP_BASE_URL`) sends a Bearer token from localStorage plus the CSRF header. On a 401 it hard-redirects to `/login`. Each domain has a `services/xxxService.js` exporting `xxxApi` functions. `guestService.js` uses its own unauthenticated axios instance. 403 limit codes (`ORG_LOCKED`, `PROJECT_LIMIT`, …) are shown once by the interceptor as a toast with an upgrade/billing link and the error is marked `__notified`.
- **Feedback UI**: toasts via `utils/toast.js` (`toast.success/error/info`, `toastError(err, fallback)` for API errors) rendered by `common/Toaster`; confirmations via `await confirmDialog({...})` (`utils/confirm.js`, rendered by `common/ConfirmHost`), never `window.confirm`. Modals use `common/Modal` (`isOpen`, `title`, Escape, `role="dialog"`) or `hooks/useEscape`. Features missing from the plan stay visible with a lock and show `common/LockedFeature` (Activity/Versions tabs via `project/SidebarTabs`, Integrations page).
- **Analytics**: PostHog in the app (`monitoring/analytics.js`, `REACT_APP_POSTHOG_KEY`/`_HOST` from root `POSTHOG_KEY`/`POSTHOG_HOST`; no-op without a key). Identifies by user id + `organization` group (no email/name), session recording off, `before_send` redacts token URLs in every string property. Product events are sent from the services: `project_created`, `pin_created`, `comment_posted`, `member_invited`. Website: GA4 in `website/public/index.html` with Consent Mode v2 (`GA_MEASUREMENT_ID`; denied until the cookie banner grants analytics; `writeCookieConsent` sends `gtag('consent','update')`). PostHog drops headless/automated browsers as bots: tests must use a normal user agent.
- **Support chat**: Crisp, via `utils/supportChat.js` (same module in `client` and `website`; `REACT_APP_CRISP_WEBSITE_ID` from root `CRISP_WEBSITE_ID`, also a `spa.Dockerfile` build arg). The script loads only when someone opens the chat; Crisp's own bubble stays hidden. Website: `ChatLauncher` button (hidden while the cookie banner is open) plus a Chat card on `/support`. App: "Chat with support" and "Help center" in the sidebar user menu. Without an ID, chat entry points are hidden and email/form remain. Website FAQs (home, support, pricing) share `components/Accordion`.
- **State**: `AuthContext` (user, role flags `isOwner/isAdmin/isGuest/canManage/canCreate/orgLocked`), `NotificationContext` and `WorkspaceContext` (`useWorkspaces()`: workspaces with project counts, `current` (remembered per org in localStorage), `select/create/rename/remove`). The dashboard shows the current workspace's projects; the sidebar `layout/WorkspaceSwitcher` switches/creates; Settings → Workspaces (`settings/WorkspacesTab`) renames/deletes. In the UI the tenant is the "organization" and "workspace" means these groups. Everything else is local hooks, with no Redux.
- **Core UX**: `components/project/ProjectView.js` (~780 lines) orchestrates `IframeContainer` (scaled device width) / `DocumentViewer` (react-pdf; pageUrl = `doc:<file>:page:<n>`), `PinListSidebar` (~1150 lines, embeds `CommentSidebar`), `NewPinCommentPopup`, and the Version/Activity sidebars. Selecting a version shows only its pins (creating a version tags all un-versioned pins, so a version is one review round; Comment mode resets to all). ## Admin (`admin/src/`)
- Superadmin only (`scripts/createSuperAdmin.js <email> <password>`); API under `/api/admin` (`routes/admin.routes.js`, `controllers/admin.controller.js`).
- Layout: dark grouped sidebar (Overview; Customers: Organizations, People, Projects; Business: Plans & pricing; Settings: Payment settings, Action log) and a top bar with `GlobalSearch` (orgs + people, `/` focuses). Shared pieces in `components/common/ui.js` (`PageHeader`, `Card`, `Button`, `Tabs`, `Avatar`, `UsageBar`, `DefinitionList`, `inputClass`) and `StatusBadge.js` (`PlanBadge`, `StatusBadge`, `RoleBadge`, `InvoiceStatusBadge`); toasts/confirm/Modal are the client's copies. List filters live in the URL (`?search=&plan=&status=&sort=&page=`).
- Org lifecycle status (`lifecycleStatus`: paying, trial, trial_ending, free, cancelling, locked, deleting) and MRR (`monthlyRevenue`: list price of active Starter/Pro, enterprise excluded) are computed server-side. `GET /admin/organizations?format=csv` exports the filtered list. The org detail returns usage vs effective limits, engagement (from `User.lastSeen`, pins/comments 30d), workspaces, pending invitations, activity, invoices and notes.
- **Admin sign-in security**:
  - **Two-step sign-in (TOTP)**: `utils/totp.js` (RFC 6238, no dependency), secrets encrypted with `utils/secretBox.js` (AES-256-GCM, key `TWO_FACTOR_KEY`, else derived from `JWT_SECRET`), 10 single-use recovery codes stored as SHA-256 hashes, replay blocked via `twoFactor.lastUsedStep`.
  - **Login flow**: with 2FA on, `POST /auth/login` returns `{ twoFactorRequired, challengeToken }` (5 min, signed with a separate key, bound to the password hash) and `POST /auth/login/2fa { challengeToken, code }` finishes it (`twoFactorLimiter`: 5 wrong codes per account per 15 min).
  - **Settings**: `GET /auth/2fa`, `POST /auth/2fa/{setup,enable,disable,recovery-codes}` (superadmin only for now; setup needs the password, disable/new codes need password + code; QR via the `qrcode` package). `ADMIN_REQUIRE_2FA` (default on when `NODE_ENV=production`) makes the superadmin middleware answer 403 `TWO_FACTOR_SETUP_REQUIRED` until it's on; the admin app then opens `/account?setup=2fa`.
  - **Lost device**: `node scripts/resetTwoFactor.js <email>` turns 2FA off and signs out all sessions.
  - **Passwords**: admin passwords need 12+ characters (`validatePassword(pw, { role })`). Superadmin reset links go to `ADMIN_URL/reset-password/:token` and expire in 30 min. `PATCH /auth/change-password` returns a fresh token (both apps store it), and a wrong current password is a 400, not 401.
  - **Admin pages**: `/login` (password, then code or recovery code), `/forgot-password`, `/reset-password/:token`, `/account` (2FA, password, name).
- `User.lastSeen` is written by the auth middleware (at most every 5 min) and on socket connect/disconnect.
- Internal notes: `AdminNote` model (never on the Organization document), `POST|PATCH|DELETE /admin/organizations/:id/notes[/:noteId]`; deleted with the org purge. The action log (`GET /admin/audit`) is Activity entries with `metadata.actorRole: 'superadmin'`; `utils/actions.js` describes every Activity action in words.

## Known issues / gotchas (verify before relying on them)
- Guest proxy iframe requests check only that sharing is enabled and not expired, not the share password (the iframe URL has no share token).
- The proxy and `/uploads` are served from the API origin; moving them to a separate sandbox domain is the remaining structural fix.
- Proxy asset URLs are query-string based (`/api/proxy?url=…`), so bundles that resolve chunks relative to their own script URL (e.g. Webflow's webpack `auto` publicPath) request `/api/<chunk>.js` and 404.
- Storage quota only counts files uploaded after quotas were added.
- Deferred (major-version) dependency upgrades: `nodemailer` 8→10 and `geoip-lite`, each with open npm advisories.
- Invoice numbers can skip a value if a settle fails after the number is assigned (rare).
- Frontend images bake in `REACT_APP_*` at build time: changing a public URL means rebuilding them.
- The API must be on its own host (`API_URL`): proxied review sites run on it and their stray requests rely on the Express catch-all.
- `.claude/` is gitignored, so agents in `.claude/agents/` are local only.
